## ১. ভূমিকা ও বাস্তব জীবনের সমস্যা (The Core Problem)

### বাস্তব জীবনের একটি উদাহরণ (Real-World Analogy):
মনে করুন আপনি একটি বড় মাল্টি-স্পেশালিটি হসপিটাল বা ডায়াগনস্টিক সেন্টারের **MLOps ইঞ্জিনিয়ার**। আপনার ডেটা সায়েন্স টিম কোটি টাকা খরচ করে একটি অত্যাধুনিক **Vision Transformer (ViT)** মডেল তৈরি করেছে, যা রোগীর বুকের এক্স-রে বা সিটি স্ক্যান ইমেজ দেখে টিউমার বা রোগ শনাক্ত করে।

এই মডেলটির ক্ষেত্রে দুটি বিশাল ঝুঁকি রয়েছে:
1. **Intellectual Property (IP) চুরি:** মডেলের ওয়েটস (weights) এবং ট্রেনিং আর্কিটেকচার কোম্পানির মূল্যবান সম্পত্তি। হ্যাকাররা মডেলের এন্ডপয়েন্টে অনবরত রিকোয়েস্ট পাঠিয়ে (Model Inversion বা Extraction Attack) মডেলের লজিক চুরি করতে পারে।
2. **ডাটা প্রাইভেসি ও PHI লিক:** রোগীর স্ক্যানে স্পর্শকাতর স্বাস্থ্য তথ্য (Protected Health Information - PHI) থাকে। 

যদি এই মডেল সার্ভারটিকে পাবলিক ইন্টারনেটে (যেমন সরাসরি Public IP দিয়ে) রেখে দেওয়া হয়, তবে:
- ইন্টারনেটের যে কেউ এতে ট্র্যাফিক পাঠিয়ে **DDoS অ্যাটাক** করতে পারে।
- FastAPI বা অপারেটিং সিস্টেমের কোনো জিরো-ডে ভালনারেবিলিটি থাকলে হ্যাকার পুরো সার্ভার হ্যাক করে মডেল এবং রোগীর ছবি ডাউনলোড করে নিতে পারে।
- কোনো এপিআই টোকেন ভুলবশত লিক হলে বহিরাগত যেকোনো ব্যক্তি মডেল অ্যাক্সেস করতে পারবে।

### সমাধান (The Solution):
**প্রোডাকশন-গ্রেড নেটওয়ার্ক আইসোলেশন (Zero Public Exposure)।**
মডেল সার্ভারটি থাকবে সম্পূর্ণ ইন্টারনেট-বিহীন একটি **প্রাইভেট ক্লাউডে (Model VPC)**। সেখানে কোনো পাবলিক আইপি থাকবে না, কোনো ইন্টারনেট গেটওয়ে (IGW) থাকবে না, এমনকি কোনো NAT গেটওয়েও থাকবে না। শুধু হসপিটালের অভ্যন্তরীণ ব্যাকএন্ড সার্ভিসেস (যা আরেকটি **Client VPC**-তে থাকবে) একটি নিরাপদ **AWS Transit Gateway (TGW)** হাইওয়ে দিয়ে মডেলটিতে ছবি পাঠিয়ে প্রিডিকশন নিতে পারবে।

## ৩. কোর নেটওয়ার্কিং কনসেপ্টসমূহ (Step-by-Step Explanation)

### ৩.১ VPC (Virtual Private Cloud) এবং CIDR Addressing
* **VPC কী?** AWS ক্লাউডের মধ্যে আপনার নিজস্ব সম্পূর্ণ ডেডিকেটেড ও সুরক্ষিত ভার্চুয়াল প্রাইভেট ডেটাসেন্টার।
* **CIDR (Classless Inter-Domain Routing):** আইপি অ্যাড্রেসের রেঞ্জ।
  * **Model VPC (`10.0.0.0/16`):** এখানে `/16` মানে প্রথম ১৬ বিট ফিক্সড। মোট আইপি সংখ্যা $2^{16} = 65,536$ টি (যেমন `10.0.0.0` থেকে `10.0.255.255`)।
  * **Client VPC (`10.1.0.0/16`):** এখানে রেঞ্জ `10.1.0.0` থেকে `10.1.255.255`।
* **কেন CIDR ওভারল্যাপ করা যাবে না?**
  * মনে করুন দুটি শহর—দুটোতেই যদি একই নামে রাস্তা এবং একই হোল্ডিং নাম্বার থাকে, তাহলে কুরিয়ার সার্ভিস বুঝতে পারবে না চিঠি কোন ঠিকানায় যাবে। 
  * দুটো VPC-র CIDR যদি একই হতো (যেমন দুটোই `10.0.0.0/16`), তবে রাউটার কখনোই বুঝতে পারত না প্যাকেটটি লোকাল নাকি পেয়ার VPC-র। তাই ইন্টার-ভিপিসি রাউটিংয়ের প্রথম শর্ত হলো **Non-overlapping CIDR**।

---

### ৩.২ Subnets (সাবনেট)
প্রতিটি VPC-কে ছোট ছোট ভাগে ভাগ করা হয়, যাদের সাবনেট বলা হয়।
* **Model Subnet (`10.0.1.0/24`):** `/24` মানে প্রথম ২৪ বিট নেটওয়ার্ক, বাকি ৮ বিট হোস্ট। এখানে ২৫৬টি আইপি (AWS ৫টি রিজার্ভ রাখে, ফলে ২৫১টি ব্যবহারযোগ্য)।
* **পাবলিক বনাম প্রাইভেট সাবনেটের পার্থক্য:**
  * একটি সাবনেটের রুট টেবিলে যদি ইন্টারনেটের রাস্তা (`0.0.0.0/0 -> Internet Gateway`) থাকে, তবে সেটি **Public Subnet**।
  * আমাদের **Model Subnet**-এর রুট টেবিলে কোনো `0.0.0.0/0` রাস্তা নেই এবং কোনো IGW অ্যাটাচ করা নেই। ফলে এটি **Strictly Private Subnet**।

---

### ৩.৩ AWS Transit Gateway (TGW) — কেন VPC Peering নয়?
* **সমস্যা (VPC Peering):** সাধারণ VPC Peering হলো পয়েন্ট-টু-পয়েন্ট কানেকশন। যদি কোম্পানিতে ২০টি VPC থাকে, তবে সবাইকে সবার সাথে যুক্ত করতে $\frac{N(N-1)}{2} = \frac{20 \times 19}{2} = 190$ টি পিয়ারিং কানেকশন লাগত, যা ম্যানেজ করা অসম্ভব।
* **সমাধান (Transit Gateway):** Transit Gateway কাজ করে একটি সেন্ট্রালাইজড **ক্লাউড রাউটার (Hub-and-Spoke)** হিসেবে। সব VPC সেন্ট্রাল TGW-এর সাথে যুক্ত থাকে এবং এটি উচ্চ ক্ষমতার প্রাইভেট ব্যাকবোনে গিগাবিট স্পিডে প্যাকেট রাউট করে।

#### TGW Attachment ও রাউটিং কীভাবে কাজ করে?
1. **Attachment:** আমরা Model VPC এবং Client VPC-কে TGW-এর সাথে যুক্ত করতে দুটি `Transit Gateway Attachment` বানিয়েছি (`tgw-attach-model-vpc` এবং `tgw-attach-client-vpc`)।
2. **Model VPC Route Table (`rtb-09626f0bf062697a4`):**
   * `10.0.0.0/16` ➔ `local` (নিজের সাবনেটের ট্র্যাফিক লোকালি চলবে)
   * `10.1.0.0/16` ➔ `tgw-07682c01476b8069e` (Client VPC-র উদ্দেশ্যে যাওয়া সব ট্র্যাফিক TGW-তে যাবে)
   * **`0.0.0.0/0` ➔ কোনো রুট নেই!** (ইন্টারনেটে যাওয়ার কোনো রাস্তাই নেই)
3. **Client VPC Route Table (`rtb-0e5e01d167e738858`):**
   * `10.1.0.0/16` ➔ `local`
   * `10.0.0.0/16` ➔ `tgw-07682c01476b8069e` (Model VPC-তে যাওয়ার রাস্তা)
   * `0.0.0.0/0` ➔ `igw-02a4fe2623e8cbf52` (ইন্টারনেট গেটওয়ে, শুধু ক্লায়েন্ট টেস্টারে SSH করার জন্য)

### ৩.৪ Security Groups (স্টেটফুল ফায়ারওয়াল)
সিকিউরিটি গ্রুপ ইনস্ট্যান্স লেভেলে ট্র্যাফিক ফিল্টার করে:
* **Model Security Group (`sg-082e53f7fed2470bb`):**
  * **ইনবাউন্ড রুল:** শুধুমাত্র `10.1.0.0/16` (Client VPC) থেকে পোর্ট `8000` (FastAPI) এবং `ICMP` (Ping) এলাউ করা।
  * **আউটবাউন্ড রুল:** ডিফল্ট এলাউড।
  * এমনকি ক্লাউডের ভেতরের অন্য কোনো অপরিচিত আইপি বা ইন্টারনেটের কোনো আইপি এই পোর্টে ঢুকতে পারবে না।

### ৩.৫ Amazon S3 VPC Gateway Endpoint
* **প্রয়োজনীয়তা:** মডেল সার্ভার যদি সম্পূর্ণ প্রাইভেট থাকে (ইন্টারনেট না থাকে), তবে সে ক্লাউডের বাইরে না গিয়ে অ্যামাজন S3 থেকে মডেল ওয়েটস আনবে কীভাবে?
* **সমাধান:** আমরা Model VPC-তে একটি **S3 VPC Gateway Endpoint** (`vpce-0d7c425217bff9419`) তৈরি করেছি।
* এটি স্বয়ংক্রিয়ভাবে Model VPC-র রুট টেবিলে AWS S3-এর প্রাইভেট প্রিফিক্স লিস্ট (`pl-6fa54006`) যুক্ত করে। এর ফলে মডেল সার্ভার সরাসরি AWS-এর অভ্যন্তরীণ অপটিক্যাল নেটওয়ার্ক দিয়ে প্রাইভেটলি S3-এর সাথে যোগাযোগ করতে পারে।

### ৪.২ FastAPI কোড স্ট্রাকচার (`/home/ubuntu/vit_server.py`)

```python
import io
import torch
from torchvision import models
from PIL import Image
from fastapi import FastAPI, File, UploadFile, HTTPException
import uvicorn

app = FastAPI(title="Private ViT Vision Model Endpoint")

# ১. মডেল লোডিং (বুটস্ট্র্যাপের সময় মেমরিতে ক্যাশ হয়)
print("[*] Loading Vision Model weights...")
weights = models.mobilenet_v3_small(weights=models.MobileNet_V3_Small_Weights.DEFAULT)
weights.eval() # ইনফারেন্স মোড
preprocess = models.MobileNet_V3_Small_Weights.DEFAULT.transforms()
categories = models.MobileNet_V3_Small_Weights.DEFAULT.meta["categories"]
print("[*] Model loaded successfully!")

@app.get("/health")
def health():
    # মডেল রেডি না হলে কখনোই রেসপন্স দেওয়া যাবে না
    return {"status": "healthy", "model": "loaded"}

@app.post("/predict")
async def predict(file: UploadFile = File(...)):
    contents = await file.read()
    image = Image.open(io.BytesIO(contents)).convert("RGB")
    batch = preprocess(image).unsqueeze(0)
    
    with torch.no_grad():
        prediction = weights(batch).squeeze(0).softmax(0)
        
    top5_prob, top5_catid = torch.topk(prediction, 5)
    
    results = [
        {"rank": i + 1, "label": categories[top5_catid[i]], "confidence": round(float(top5_prob[i]), 4)}
        for i in range(top5_prob.size(0))
    ]
    
    return {
        "success": True,
        "filename": file.filename,
        "top_prediction": results[0]["label"],
        "confidence": results[0]["confidence"],
        "top_5": results
    }

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### ৪.৩ ব্যাকগ্রাউন্ড সার্ভিস ম্যানেজমেন্ট (`systemd`)
প্রোডাকশনে স্ক্রিপ্ট টার্মিনালে ম্যানুয়ালি চালানো হয় না। এটি একটি ডেমন হিসেবে চলে:
- **সার্ভিস ফাইল:** `/etc/systemd/system/vit-server.service`
- এটি নিশ্চিত করে যে যদি সার্ভার রিবুটও হয়, তবে নিজে থেকেই Uvicorn ও FastAPI ব্যাকগ্রাউন্ডে চালু হয়ে যাবে এবং ক্র্যাশ করলে ৫ সেকেন্ডের মধ্যে অটো-রিস্টার্ট হবে।

## ৫. টেস্ট ও ভেরিফিকেশন (Negative vs Positive Testing)

সিকিউরিটি ইঞ্জিনিয়ারিংয়ের মূল নীতি হলো: **সিস্টেম শুধু কাজ করলেই হবে না, নিষিদ্ধ পথে যে কাজ করে না সেটাও প্রমাণ করতে হবে।**

### টেস্ট ১: Negative Testing (পাবলিক ইন্টারনেট থেকে অ্যাক্সেস চেষ্টা)
* **কমান্ড (আপনার নিজস্ব লোকাল কম্পিউটার থেকে):**
  ```bash
  curl -m 3 http://10.0.1.140:8000/health
  ```
* **রেজাল্ট:** **Connection timed out!**
* **কেন ফেইল করল?**
  1. আইপি `10.0.1.140` হলো RFC 1918 প্রাইভেট আইপি রেঞ্জ—পাবলিক ইন্টারনেট রাউটারে এটি নন-রাউটেবল।
  2. Model Server-এর কোনো পাবলিক আইপি নেই।
  3. Model VPC-তে কোনো ইন্টারনেট গেটওয়ে বা ডিফল্ট রাউট নেই। ফলে বাইরের কোনো প্যাকেট সার্ভার পর্যন্ত পৌঁছানো শারীরিকভাবে অসম্ভব।

## ৬. ইন্টারভিউতে এই ল্যাবটি কীভাবে উপস্থাপন করবেন?

যদি কোনো ইন্টারভিউয়ার আপনাকে জিজ্ঞাসা করে:  
> *"How do you securely deploy a machine learning model on AWS without exposing it to the internet?"*

আপনি সরাসরি এই ল্যাব ১-এর আর্কিটেকচার পয়েন্টগুলো উল্লেখ করবেন:

1. **Defense in Depth (নেটওয়ার্ক আইসোলেশন):**
   > *"আমি মডেল সার্ভারকে সম্পূর্ণ ইন্টারনেটরহিত একটি ডেডিকেটেড Private VPC-তে রাখি যেখানে কোনো Public IP বা Internet Gateway থাকে না। আউটবাউন্ড বা ইনবাউন্ড কোনো 0.0.0.0/0 রুট থাকে না।"*
2. **Transit Gateway (TGW) Hub-and-Spoke:**
   > *"ইন্টারনাল মাইক্রোসার্ভিস বা ক্লায়েন্ট অ্যাপ্লিকেশনের সাথে মডেল সার্ভারকে কানেক্ট করার জন্য আমরা AWS Transit Gateway ব্যবহার করি। এটি VPC Peering-এর মেস জটিলতা দূর করে সেন্ট্রালাইজড প্রাইভেট রাউটিং নিশ্চিত করে।"*
3. **Least Privilege Security Groups:**
   > *"মডেল সার্ভারের সিকিউরিটি গ্রুপে শুধুমাত্র ক্লায়েন্ট VPC-র CIDR ব্লক থেকে নির্দিষ্ট পোর্টে (যেমন TCP 8000) ট্র্যাফিক অনুমোদন করা হয়।"*
4. **S3 Private Access via Gateway Endpoint:**
   > *"মডেলের নতুন ওয়েটস বা আর্টিফ্যাক্ট নিরাপদে ফেচ করার জন্য আমরা Model VPC-তে S3 Gateway Endpoint যুক্ত করি, যা ইন্টারনেটে না গিয়ে সরাসরি এডব্লিউএস-এর অভ্যন্তরীণ ব্যাকবোনে S3 ট্র্যাফিক রাউট করে।"*
5. **FastAPI Readiness Probes:**
   > *"FastAPI সার্ভারে `/health` এন্ডপয়েন্ট মেমরিতে মডেল ওয়েটস লোড হওয়ার পরেই কেবল HTTP 200 দেয়, যাতে আর্লি রিকোয়েস্ট এসে ফেইল না করে।"*
6. **Negative Penetration Testing:**
   > *"ডিপ্লয়মেন্টের পর সবসময় পাবলিক ইন্টারনেট থেকে নেগেটিভ টেস্ট চালিয়ে টাইমআউট নিশ্চিত করি এবং ইন্টারনাল ক্লায়েন্ট থেকে পজিটিভ টেস্ট চালিয়ে এন্ড-টু-এন্ড সাব-১০০ মিলি-সেকেন্ড ল্যাটেন্সি ভেরিফাই করি।"*
